# 自动化运行详细流程（每天自动获客）

本文档把「每天自动获客」从一句口号，拆成**可以每天重复执行的完整流程**，包括：工作目录约定、首次全量 vs 每日增量、定时任务配置、每日产出物、人工审核节点。

> **核心原则**：自动化负责「抓取 → 筛选 → 评分 → 写信 → 整理」，**发送永远人工**。你的账号安全 > 自动化速度。

---

## 一、工作目录约定（先建好目录）

为了让每天的数据不混乱、可追溯，建议固定一个本地工作目录：

```
D:\masterbatch-leadgen\
├── market-plan.csv             ← 市场轮换表（目标市场可配置，每天可换）
├── leads\                      ← 线索池（每日累积，不覆盖）
│   ├── 2026-11-12-leads.csv    ← 每天一份
│   └── master-lead-pool.csv    ← 总池（合并去重后，多键唯一）
├── outreach\                   ← 开发信草稿
│   └── 2026-11-12-drafts.md
├── reports\                    ← HTML 日报（每天一份，双击打开）
│   └── 2026-11-12-daily-report.html
├── review\                     ← 审核结果
│   └── 2026-11-12-review.md
└── logs\                       ← 运行日志
    └── 2026-11-12-run.log
```

> **命名规则**：所有文件带日期前缀，方便追溯，也方便"每日增量"只处理新线索。

## 二、两种运行模式（关键区别）

| 模式 | 何时用 | 做什么 | 输出 |
|---|---|---|---|
| **每日固定抓取** | 每天（周一到周五 9:20 自动，周六周日手动触发） | 每天抓取 **50 家真实客户数据**（去重后），全部评分分级 | 当日 50 家新线索 + 开发信 + HTML 日报 |

> 🔴 **每天固定 50 家真实数据（铁律，2026-11-24 起由 30 家上调）**：每天跑完后，**当日实际入库的去重后真实客户数必须达到 50 家**（不是"最多搜 50 家"、也不是"搜了 50 家但只筛出 5 家"）。搜索时可以多搜（60-70 家候选），但**经过去重、剔除色母粒同行、剔除信息不实后，最终有效客户要凑满 50 家**。达不到就换关键词/换城市/换行业继续补搜，直到凑满。

> 🔴 **保留硬门槛（2026-11-24 起 · 用户铁律）**：**每家客户必须有「邮箱」或「WhatsApp 账号」二者至少其一，否则一律剔除**（原因写「无邮箱且无WhatsApp」）。只有电话、没有邮箱也没有 WhatsApp 的客户不算有效客户，不纳入 50 家。此门槛已在 `classify_leads.py` 内实现（评分前即剔除），无需人工判断。

> 🔴 **入库兜底门槛（2026-11-24 追加 · 用户铁律）**：`import_leads.py` 也已内置同样的硬门槛（`contactable()`），候选客户「无邮箱且无社交账号（WhatsApp/Zalo/LINE/KakaoTalk 任一真实号）」一律拒绝入库，输出「拒绝(无邮箱且无社交)」明细。这是**最后一道防线**，防止未来有数据绕过 classify 直接走 import 混入总池。
>
> 🔴 **总池已清理（2026-11-24）**：历史遗留的「既无邮箱又无社交账号」客户已用 `tools/purge_uncontactable.py` 一次性移出 `master-lead-pool.csv`（409 → 181 家），被剔除的 228 家保留在 `leads/剔除-无联系方式.csv` 供人工复核，未物理删除。若哪天要复核或补挖这些客户，读该文件即可，不要重新抓。

## 二·五、目标市场可配置（每天可换国家/地区）

**核心机制**：目标市场**不锁死**，由一份「市场轮换表」驱动。每天运行前，先读取/决定"今天攻哪个市场"，再针对该市场搜线索。这样能**覆盖多个国家，又不会每天重复抓同一市场**。

> **市场优先级怎么定？** 不是拍脑袋，而是按**全球色母粒进出口数据**排序（需求体量 × 增长 × 对华友好度 × 准入难度）。完整 30 国分析和四档 Tier 分级见 [`market-priority-ranking.md`](market-priority-ranking.md)。简版结论：**Tier 1 = 越南 > 印尼 > 印度 > 巴基斯坦 > 泰国 > 马来（立即开发）；Tier 2 = 沙特 > 墨西哥 > 土耳其 > 巴西 > 阿联酋 > 孟加拉 > 菲律宾 > 埃及 > 尼日利亚；Tier 3 = 哥伦比亚/智利/阿根廷/南非/波兰（机会型）；Tier 4 = 美/日/韩/德/意/英/法/澳/加（高价值高门槛，有资质后专攻）**。

```

**字段说明**：
- `market`：市场代号（国家名）
- `country` / `region`：国家和地区
- `language`：该市场主语言（决定搜索关键词和开发信语言）
- `status`：`active`（轮换中）/ `pending`（暂不启用）/ `done`（已充分开发）/ `stocked`（存量已够开发，暂停抓新客、等人工触达推进）
- `priority`：轮换优先级（1-50，数字越小越优先，欧美日韩排最前）
- `last_run`：上次开发日期（判断"该轮到谁"）

### 每日市场选择规则（按此决定今天攻哪）

> 🔴 **不再默认越南**。市场切换由「A 级枯竭 + B 级不足」触发，从 50 国按优先级自动切。
>
> ⚙️ **别再靠人脑判断——直接跑选择器**（唯一裁判，规则全在代码里）：
> ```bash
> python tools/pick_market.py            # 看今天选谁
> python tools/pick_market.py --date 2026-11-20   # 预演某天（如周五）
> python tools/pick_market.py --apply     # 顺带把判定的 stocked 落盘
> ```
> 最后一行输出 `MARKET=<市场>`，自动化直接取用。

### 双轨道：main（周一~周四）+ wa（周五 WhatsApp 专项日）

| 轨道 | 何时跑 | 市场来源 | 目标 |
|---|---|---|---|
| `main` | 周一~周四 | `track=main` 且 `status=active`，priority 最小者 | 攒合格客户（邮件为主） |
| `wa` | **周五** | `track=wa`：印尼 → 印度 → 土耳其，按 `last_run` 最久远轮换 | **攒 WhatsApp 号**（聊天为主） |

**为什么单开周五**：`main` 前 12 位全是欧美日韩，B2B 基本不用 WhatsApp（实测 155 个官网仅 3 家挂 wa.me），按主线轮换要等两周多才轮到印尼(#14)/印度(#15)。周五专攻 WhatsApp 高渗透市场，一周攒一批真号，其余四天不受影响。

**周五专属要求**（其它步骤与 main 轨道完全相同）：
1. 抓完 30 家后**必须**跑 `python tools/find_whatsapp.py --crawl --market <市场>`，把「官网自挂 wa.me」的数量写进日报（这是周五的核心 KPI，不是附带）。
2. 日报额外给三项：**WhatsApp 覆盖数 / 待验数 / 本周累计新增号**。
3. 语言：印尼→印尼语+英语、印度→英语、土耳其→土耳其语；开场白当地语言示例见 `outreach-templates.md`。
4. 存量积压规则**对 wa 轨道不生效**——这些市场就是用来攒号的，不该因为"存量够了"被跳过。

1. **首次运行 / 无历史记录** → 从 50 国优先级最高的市场开始（默认欧美日韩优先，即美国/德国/日本/韩国…），每天抓取 30 家真实数据，建立该市场基础池。
2. **切换条件（可计算版 · 关键）**：当前市场**同时**满足以下两条，就切到下一个市场：
   - **A 级"已开发完"**＝该市场 A 级客户中，`跟进状态 ≠ 未联系`（已发信/已回复/已报价/已寄样/成交/无效）的占比 **≥ 90%**；
   - **B 级剩余 < 10** ＝该市场 `跟进状态 = 未联系` 的 B 级客户数 **< 10**。
   > ⚠️ **"开发完"不等于"池里有"，而是"已经动过"**。池子里的 A 级再多，只要还是`未联系`，就不算开发完。
   > 这就是为什么线索池必须有 `跟进状态` 字段——**没有它，切换条件无法判定，市场会永远卡在同一个国家**。
3. **每天开跑先算这个数**（30 秒，用总池直接算，结果写进日报头部）：
   ```bash
   python -c "
   import csv
   from collections import Counter
   rows=list(csv.DictReader(open('master-lead-pool.csv',encoding='utf-8-sig')))
   m='美国'  # 换成当前市场
   sub=[r for r in rows if r['国家']==m]
   a=[r for r in sub if r['等级']=='A']; b=[r for r in sub if r['等级']=='B']
   a_done=sum(1 for r in a if r['跟进状态']!='未联系')
   b_left=sum(1 for r in b if r['跟进状态']=='未联系')
   print(f'{m}: A级{len(a)}家(已开发{a_done}, {a_done/max(len(a),1):.0%}) | 未联系B级{b_left}家')
   print('→ 应切换' if (a_done>=0.9*len(a) and b_left<10) else '→ 继续本市场')
   "
   ```
4. **存量积压强制轮换（2026-11-16 新增 · 防"永远卡在第一个国家" · 仅 main 轨道生效，wa 轨道不适用）**：因为对外发送全靠人工，`跟进状态` 长期全是`未联系`，上面第 2 条的切换条件实际上永远不触发。故补一条硬规则：
   - 当前市场**累计线索 ≥ 60 家** 且 **未联系 A 级 ≥ 10 家** → 判定为「存量已够开发」，**强制轮换到下一个 priority 市场**，并在日志/日报写「本轮跳过 <国家>：存量 N 家、未联系 A 级 M 家，转 <新国家>」；
   - 该市场状态改为 `stocked`（在 market-plan.csv 的 status 列标记），等人工把 A 级发过一轮（`跟进状态` 有推进）再回来续抓；
   - 轮换不是放弃：美国池 139 家、A 级 27 家，够你发 3 周；先把它发出去，再回来补新城市。
   > 一句话：**抓新客的钱已经花够了，现在缺的是把已有的发出去。** 存量轮换只是把"抓取火力"挪到还没开荒的国家，不减少每日 30 家。
5. **切换方向**：按 `market-plan.csv` 的 `priority` 从小到大切（1→2→3…50），跳回时也从最高优先级开始。重点市场（欧美日韩）优先。
6. **一天一个市场**（或一天最多 2 个），避免贪多嚼不烂、关键词混乱。
7. 某个市场连续多天新增线索极少（<3 家）→ 标记 `done` 或降 `priority`，把火力转给新市场。
8. **换市场时自动切换语言**：美国/英国→英语；德国→德语；日本→日语；韩国→韩语；越南→越南语；土耳其→土耳其语；墨西哥→西语。关键词库见 `multilingual-keywords.md`（或直接 `python tools/kwgen.py --list`）。
9. **存量优先提示（不违反每日 30 家铁律）**：每天仍抓 30 家新客户续池，但**日报头部必须显著提示"该市场未联系的 A 级 N 家"**，并列出「今日最该发的 10 家」（未联系 A 级、官网产品已补、带三语开场白复制块）——池子只进不出是最常见的浪费：攒了 27 个 A 级却一个没发，等于零。

### 如何手动指定"明天攻哪个市场"

用户随时可以改。三种方式：
- **直接说**："明天攻土耳其" → 把 `market-plan.csv` 里土耳其的 `last_run` 置空/优先级调 1。
- **改 CSV**：手动编辑 `market-plan.csv` 的 `status`/`priority`。
- **加新市场**：在 CSV 里加一行（country/region/language 填好），下次自动纳入轮换。

## 三、每日自动流程（Day by Day）

### 每天固定跑这 10 步（AI 全自动）

```
【每日获客流程 · 自动执行】

0. 同步跟进   → 先同步人工跟进状态（**必须在"定市场"之前**，否则切换条件算的是昨天的旧状态）。**优先用 `--auto` 自动扫描**：它会自动找桌面/下载/工作目录里最新的 `跟进进度-*.csv`（跟进台导出）和 `已发清单-*.csv`（发信队列导出），把人工点的「已发信/已回复…」和「已发送」回写进 `master-lead-pool.csv`；都找不到才读《客户跟进表.xlsx》：
    ```bash
    python tools/sync_followup.py --auto          # 预演看差异
    python tools/sync_followup.py --auto --commit # 差异合理则写入（自动备份 + schema_check，失败回滚）
    ```
    > 🔴 **这是「跟进状态」唯一的回写通道**：发信队列勾「已发送」、跟进台点状态，都只存浏览器 localStorage，必须靠导出 CSV + `sync_followup.py` 回写，AI 直接读 localStorage 读不到。导出动作：发信队列点「导出已发清单」、跟进台点「导出进度」，各得到一个 CSV 落到下载/桌面，`--auto` 会自动捡到最新的。
    > 人工想手动指定时：`--from-csv <跟进进度csv>`（跟进台）或 `--from-sent <已发清单csv>`（发信队列），也可两者同给（显式状态优先于「已发信」）。
    > 只回写 `跟进状态` / `最后联系日` 两列，不碰其它字段。
1. 定市场     → 按"切换规则"决定今天攻哪个国家（不默认越南；**A 级「已动过」占比 ≥90% 且未联系 B 级 <10**、或**存量积压规则触发**就切下一个，从50国按优先级切，欧美日韩优先；开跑先算这个数并写进日报）；同一市场多日开发要**换城市/州**（见"城市/州轮换"）
2. 抓取客户   → **走地图流水线，不手工拼词**：① `python tools/kwgen.py --country <市场> --tier all --cities 3 --cmd` 自动出本地语言关键词+换城（记账在 `logs/_kw_rotation.json`）② 执行它给出的 `tools/maps_scrape.py` 命令抓 50+ 候选（脚本在工作目录 `D:\masterbatch-leadgen\tools\`）③ 深挖后跑 `python tools/classify_leads.py ... --deepdive ...` 甄别真工厂（强排除同行/回收/设备，弱排除贸易，品类误判可用公司名工艺词推翻；**无邮箱且无WhatsApp 直接剔除**）并判配色/阻燃需求。地图不可用才降级 WebSearch（日志注明原因）
   > 🔴 **谷歌地图搜索规则（2026-11-24 起）**：一律按「**国家 + 城市 + 行业关键词**」组合搜，例如 `"South Korea" "자동차 부품 사출 성형 부산, 플라스틱 사출 성형 인천"`。**搜不够 50 家就换关键词**——注塑(`inj`)、吹膜(`film`)、挤出(`ext`)、吹瓶/吹塑(`blow`)、管材(`pipe`)、包装(`pkg`)、型材(`profile`) 等工艺词都能用，轮换着搜，直到凑满 50 家。**绝不为了凑数而下调「邮箱/WhatsApp 二选一」或「真工厂」甄别标准**。
3. 多维去重   → `python tools/import_leads.py <candidates.csv>` 预演 → `--commit` 写入（官网域名/邮箱域名/电话尾号/公司名模糊 四键去重，已存在只补空字段不覆盖；见下方"去重规则"）
4. 信息提取   → 提取公司名、业务、材料、官网、联系方式
5. 线索评分   → 按 7 维打分分级（A/B/C）
6. 深挖       → 对 A 级 + B 级客户做【浏览器深挖（第一优先，开真实 Chrome 实时抓官网/联系页/决策人/footer 社交链接）+ 搜索兜底】+ 决策人实名 + 社交双渠道必查（按市场：欧美 WhatsApp/LinkedIn、越南 Zalo、韩国 KakaoTalk、日本 LINE、泰国 LINE、中东/拉美 WhatsApp）+ 社交深挖。浏览器深挖的具体命令、端口探测、降级规则见 `references/browser-deep-dive.md`
6.5 挖聊天号 → 深挖完立刻补 WhatsApp：`python tools/find_whatsapp.py --crawl --market <市场>`（抓官网 wa.me + 池内手机号段推断）→ `python tools/render_wa_worklist.py` 出点验清单。**高置信（官网自挂 wa.me）直接可用；中置信必须点链接验**；美/日/韩别在这上面耗时间（B2B 基本不用），越南主通道是 Zalo。见 `whatsapp-sourcing.md`
7. 开发信草稿 → **双通道，两种写法不能混**：①**WhatsApp（Zalo/LINE/KakaoTalk）严格两句**——我是谁+做什么 / 痛点判断+零成本提问；②**邮件一整封**——独立 `Subject:` 行 + 4 段正文（锚点洞察→工厂身份→针对能力→CTA）+ 真实签名块。两者都要**英语发送版 + 中文参照版**（缺一不可），当地语言作示例版；签名与实力数据取 `company-profile.md` 真实信息，禁止占位符；**正文第一段必须锚定对方官网真实产品**（拿不到则标注 `⚠️ 个性化降级`）；写法见 `outreach-templates.md` 2.4 与第七章
8. 合规审核   → 跑一遍发送前检查清单
9. 整理归档   → **先跑 `python tools/schema_check.py`（21列表头一致/总分纯数字/等级∈ABC/跟进状态合法/官网非目录站）**，再写入当日 CSV + 合并进总池（去重后合并）
10. 生成日报  → 生成 HTML 日报文件 + 今日待办清单，并按「日期+国家」在桌面建当天文件夹统一归档（见下方"每日产出归档到桌面"）
```

### 每日产出归档到桌面（日期+国家命名，铁律）

> 🔴 **每天生成的客户数据，必须在桌面建一个"当天文件夹"统一存放**，不要散落在工作目录里。

- **桌面路径**：`C:\Users\<用户名>\Desktop\`
- **文件夹命名规则**：`YYYY-MM-DD-国家`，例如 `2026-11-13-越南`、`2026-11-14-德国`、`2026-11-15-韩国`。
- **当天文件夹里放什么**：把当天的全部产出物复制/生成一份进去——
  - 当日线索池 `YYYY-MM-DD-leads.csv`
  - HTML 日报 `YYYY-MM-DD-daily-report.html`
  - 开发信草稿 `YYYY-MM-DD-drafts.md`
  - 今日待办清单 `YYYY-MM-DD-todo.md`
- **主工作目录仍保留一份**：`D:\masterbatch-leadgen\` 继续作为去重总池、跨天累积的数据源（`master-lead-pool.csv` 只在这里，桌面文件夹是"当天快照"）。

### 去重规则（杜绝重复客户 / 重复数据，必严格执行）

> **目标**：同一个客户，无论搜到多少次、来自哪个渠道、名字怎么变，都**只保留一条**。

**多键去重（按优先级依次匹配，命中任一即视为重复）**：

1. **官网域名归一化**（最可靠）：`www.example-factory.vn`、`example-factory.vn`、`https://example-factory.vn/vi/contact` → 统一成 `example-factory.vn`（去掉 `www.`、`http(s)://`、子路径、末尾 `/`）。域名相同 = 同一家。
2. **邮箱域名**：`info@xxx.com`、`sales@xxx.com` → 域名 `xxx.com` 相同 = 同一家（同一公司不同邮箱）。
3. **电话/WhatsApp 号码归一化**：去掉空格、`+`、`-`、括号，统一成纯数字（`+84 123 456 789` → `84123456789`）。号码相同 = 同一家。
4. **公司名模糊匹配**：去掉 `Co.`、`Ltd`、`JSC`、`Corporation`、`Công ty`、`TNHH`、`JSC`、标点、大小写后做包含匹配。如 "Example Plastics Co., Ltd" ≈ "EXAMPLE PLASTICS"。
5. **税号/企业统一编码**（若有）：越南 MST、土耳其 VKN 等，唯一性最强，命中必判重。

**归档时的二次去重**：写入总池 `master-lead-pool.csv` 前，再做一遍全表去重，确保总池内无重复行。

### 入库前必做：数据质量校验（防字段错位，铁律）

> 🔴 历史上出现过两类静默错误：① 「行业」字段含未转义逗号导致整行右移（`总分` 列变城市名、`等级` 变 33）；② 7 维分数之和与总分不一致。**每次写总池前必须跑校验器，任一条不通过就修好再写：**

```bash
# 校验总池（21 列表头 + 等级/总分/跟进状态 + 目录站污染 + 重复）
python tools/schema_check.py

# 校验当日 CSV（21 列基础 + 7 维明细，会额外校验「7维之和 == 总分」）
python tools/schema_check.py leads/YYYY-MM-DD-<国家>-leads.csv
```
退出码 `0`=通过，`1`=有错误（**必须中止入库并修好**）。

**校验器拦截项**（`tools/schema_check.py`）：
1. 表头必须是规范 21 列且**顺序一致**（防错位）；
2. 每行列数一致（防未转义逗号）；
3. `总分` 纯数字、`等级` ∈ {A,B,C}、`跟进状态` ∈ {未联系,已发信,已回复,已报价,已寄样,成交,无效}；
4. 当日 CSV 额外校验 **7 维之和 == 总分**、每维 ∈ 0-5；
5. **`官网` 不得是目录站/数据商/社交平台**（thomasnet / contactout / growjo / rocketreach / zoominfo / dnb / manta / yellowpages / kompass / europages / alibaba / indiamart / linkedin / facebook 等）——填了这些等于没有官网，官网锚点无从提取；
6. 公司名/官网域名重复告警。

**规范 21 列（总池与当日 CSV 基础字段必须完全一致）**：

```
排名,国家,公司名,行业,城市,总分,等级,官网,邮箱,电话,联系人,职位,
WhatsApp,Zalo,LINE,KakaoTalk,官网产品,跟进状态,最后联系日,切入建议,来源
```

> **两道关键设计**：`跟进状态` 决定市场能否切换（见切换条件）；`官网产品` 决定开发信能否做到"公司级个性化"（见 `outreach-templates.md` 第二章）。这两列空着，整套流程就退化成"只进不出的名单收集器"。

### 人工跟进表：`客户跟进表.xlsx`（AI 备料 ↔ 人工触达 的接口）

池子决定"该发谁"，跟进表决定"发了什么、对方怎么回"。两个文件分工固定：

| 文件 | 谁写 | 作用 |

- **建表脚本**：`.客户跟进表.ref/build.py`（改版式/加列时改这个再重跑，不要手改 xlsx 后再跑脚本，会覆盖手改内容）。

### 同一市场多日开发：城市/州轮换（防止重复搜索）

> 同一个国家连续开发多天时，搜索引擎返回的头部结果高度重叠，容易反复搜到同一批公司。**美国已累计 112 家、德国/日本等尚未开荒**，因此：

- **每个市场记录「已搜城市/州」**（可写在 `logs/` 下当日日志里），下次换一批城市。
- 示例：美国 Day1 搜 Ohio/Michigan/Indiana，Day2 搜 Texas/California/Illinois，Day3 搜 North Carolina/Georgia/Wisconsin…
- 若某市场连续 2 天新增去重后 < 3 家 → 视为该市场「搜索引擎已挖尽」，按切换规则转下一个 priority 市场。

**重复数据的三条硬纪律**：
- 搜到已存在客户 → **直接跳过**，不重复评分、不重复写信、不重复进池。
- 同一客户有新信息（如新挖到 WhatsApp/决策人）→ **合并更新**原记录（补字段），而不是新增一行。
- 每次运行结束，在日志里记录「去重 N 条、新增 M 条、合并 K 条」，保证数据可审计。

## 六、每日流程的完整提示词（一键版）

【步骤】

2. 抓取（**走地图流水线，禁止手工拼关键词**）：

   c) `python tools/import_leads.py "leads/<日期>-candidates-<地区>.csv"` 先预演看命中，确认后加 `--commit`（四键去重，已存在只补空不覆盖，写库前自动备份）
   > 合格数 <50 时：**扩城市/扩工艺**（改 kwgen 的 `--cities 5`、`--industry inj,ext,film,blow,pipe,pkg,auto,cable`）重跑，不许下调甄别阈值。待确认桶留人工判断，不硬凑进 A/B。
4. 信息提取：公司名、业务、使用材料、官网（**必须是客户自有域名，禁止填 thomasnet/contactout/growjo/rocketreach 等目录站或数据商**）、公开联系方式（按市场挖 WhatsApp/Zalo/KakaoTalk/LINE）
5. 评分：按 7 维打分分级（A/B/C），标出 A 级和 B 级
6. 深挖：对 A 级 + B 级客户（同等待遇）做【浏览器深挖第一优先 + 搜索兜底】。**浏览器深挖**（见 `references/browser-deep-dive.md`）：主通道是**用户自己的 Chrome**（`BU_NAME=mainchk browser-use`，**不带 BU_CDP_URL**，走系统代理，Google 搜索/地图才通）；先跑 `python tools/maps_scrape.py "<地区>" "<关键词1>,<关键词2>,..."` 从谷歌地图分片抓客户，再跑 `python tools/site_deepdive.py "leads/<日期>-map-<地区>.json" 40` 逐个打开官网抓 真实URL/邮箱/电话/footer 社交链接/决策人。**硬性验收**：A/B 级官网打开率 ≥80%，日报写「深挖覆盖率 X/Y」。**降级兜底**（登录墙/反爬/官网失效时转 WebSearch）：决策人用 `"公司名" "procurement/supply chain/general manager"`；社交主页用 `site:facebook.com "本地语言公司名"`、`site:linkedin.com/company/ "公司名"`（LinkedIn 只手动搜、绝不自动化加好友/私信）。
   - 🔴 **深挖必须产出「官网产品」**：打开官网的产品页（Products / 产品中心 / Produkte / 製品情報 等），抄下**2-5 个具体产品名 + 用到的树脂**，写进线索池 `官网产品` 列。这是开发信"公司级个性化"的唯一数据来源——**没有官网产品，就只能写群发腔**（见 `outreach-templates.md` 第二章）。拿不到就填 `⚠️未获取（原因）`，不许留空、更不许编。
   - **决策人拆两列**：`联系人` 只写姓名（如 `Steven Ames`），`职位` 单独一列（如 `Director of Sales`）；历史行里 `姓名(职位)` 混在一起的标 `待拆分`，后续补齐。
   - **社交按市场填对应列**：WhatsApp / Zalo / LINE / KakaoTalk 各归其位；该市场不用的渠道填 `该市场不使用—`（**不要为了填满而编号码**）。
   - **补 WhatsApp 号**：`python tools/find_whatsapp.py --crawl --market <市场>` 抓官网 `wa.me` 链接 + 用号段规则判池内电话是否手机 → `python tools/render_wa_worklist.py` 生成点验清单 `reports/whatsapp-candidates.html`。**只有「官网自挂 wa.me」才可直接写库；号段推断的标「待验证」等人工点链接确认**；无证据的把 `WhatsApp` 填 `该市场不使用—` 或 `待核实`，禁止编号码。
7. 开发信：为 A/B 级写**三语版**——`【英语·发送版】`（每封必写）+`【中文·参照版】`（每封必配，永不外发）+`【当地语言·示例版】`（有把握才主发，否则用"英语 + 一句当地问候"，**绝不机翻长句**）。正文必须锚定该客户 `官网产品` 列里的真实产品/树脂（如 "saw you mold PC/ABS bezels for appliance OEMs"），只写 "plastic industry" 视为不合格退回重写；官网产品为空则标 `⚠️个性化降级`。模板见 `references/outreach-templates.md`。
8. 审核：跑一遍发送前合规检查清单——**先跑机检** `python tools/audit_outreach.py --src <当日 leads CSV>`（首次发信六条禁令：公司历史/价格/产品罗列/月采购量/群发腔/无证据认证；退出码 1＝有违规，必须改到 0 再往下走），**再过人检**（公司名、产品、资质、占位符）。六条禁令的正反例见 `outreach-templates.md` 2.7
9. 归档：当日合格线索用 `import_leads.py --commit` 入库（已去重合并）；更新 market-plan.csv 的 last_run；日志写「抓到N/合格M/剔除K/待确认J/新增X/合并Y/深挖覆盖率」
10. 生成日报 + 桌面归档：**用统一生成器出日报，不要每天手写一次性脚本**
    ```bash
    python tools/render_report.py logs/_leads_<日期>.json reports/<日期>-daily-report.html <市场> <日期>
    # 同时重建两页
    python tools/build_followup_html.py     # 逐家跟进台
    python tools/render_sendlist.py         # Gmail 发信队列（一封一点，点开即填好收件人/主题/正文）
    ```
    > 🔴 **发送永远是人工的**：队列页只给「用 Gmail 打开发送」深链，不代发、不自动 send。
    > 一次性群发 27 封冷邮件会触发 Gmail 风控（先进垃圾箱、再限权），且欧盟 GDPR / 加拿大 CASL
    > 对未经同意的商业邮件有法律要求。日报只写「今日最该发的 N 家」，不写发送数。
    日报必含（A/B/C 全量排名 + 7维分数条 + 逐维理由 + A/B级决策人姓名/职位分两行 + 社交渠道按市场拆行 + **官网产品** + **跟进状态** + 三语开场白一键复制 + 顶部「未联系A级N家」红字提示）＋ 今日待办清单，并在日志记录「去重N条/新增M条/合并K条」；**入库前先跑 `python tools/schema_check.py`**；然后在桌面 `C:\Users\<用户名>\Desktop\` 建当天文件夹 `YYYY-MM-DD-国家`，把当日线索池/日报/开发信/待办清单复制进去
    > 🔴 日报是头号交付物，**必须用 `tools/render_report.py` 统一出**：手写脚本每天重造既容易漏字段，也容易风格漂移。该脚本对缺失字段优雅降级（显示"—"），但**降级项本身就是质量警报**——"公式参照版全空""官网产品全空"必须当场补。

11. **每天数据单独出，不与总池混（用户硬性要求，2026-11-23 起执行）**
    ```bash
    # 一键生成「当天独立」产出物：发信队列 / 当日线索CSV / 待办 / 开发信草稿 / 桌面归档
    python tools/archive_daily.py <日期> <市场>
    ```
    > 🔴 **铁律：当天的发信队列、线索 CSV、待办、开发信草稿，必须从「当天数据」生成，绝不能读总池 `master-lead-pool.csv`。**
    > - `archive_daily.py` 读当天 `logs/_leads_<日期>.json`（或 `leads/<日期>-leads.csv`），产出的 `reports/<日期>-sendlist.html` 只含当天客户。
    > - 全池 `gmail-sendlist.html`（带市场筛选下拉框）与跟进台 `customer-followup-desk.html` 是「常驻工具」，放桌面根目录，**不要混进当天文件夹**——当天文件夹只留纯当天数据。

    > - ⚠️ `audit_outreach.py` 的 `--csv` 是「审核报告输出路径」，**不要把它指向 candidates 源文件**（会覆盖当天数据）；要指定输入源用 `--src`。

## 八、常见问题

**Q1：每天跑会重复抓到同一批公司吗？**
不会——第 3 步"多维去重"会用**官网域名/邮箱域名/电话归一化/公司名模糊匹配**多键对比总池，已存在的自动跳过；同一客户的新信息会"合并更新"而非新增。

**Q2：需要每天换关键词吗？**
换市场时自动切换该市场的语言关键词（见 `multilingual-keywords.md`）；同一市场内建议每周微调一次。

**Q3：A 级客户太多/太少怎么办？**
见 `lead-scoring.md` 的"分级标准"——A 级应占 10%-20%，偏差大就调评分门槛或换数据源。

**Q4：自动化会不会导致被封号？**
不会——因为发送环节永远是人工手动。AI 只做"本地备料"，不触碰任何平台账号。

**Q5：怎么让机器人明天去开发别的国家？**
改 `D:\masterbatch-leadgen\market-plan.csv`：把目标市场的 `status` 设为 `active`、`last_run` 清空，或直接对 AI 说"明天攻土耳其/墨西哥"。详见"二·五、目标市场可配置"。

**Q6：Facebook/LinkedIn 深挖为什么总搜不到目标公司？**
多半是**用错了语言和平台**。越南/东南亚中小厂的 Facebook 主页名是本地语言（如 "Công ty Nhựa XXX"），英文名搜不到；正确做法是**先解析官网 `facebook.com/xxx` 链接**直接定位官方主页（零噪声），而不是去 Facebook 站内搜。LinkedIn 则相反——**搜人比搜公司难**，未登录有登录墙、免费账号有搜索次数上限，所以公司页用 `site:linkedin.com/company/` 让 Google 搜，决策人用 `"公司名" "procurement"` 站内搜，且**只手动、绝不自动化**（否则封号）。完整关键词见 `multilingual-keywords.md` 第五章。

**Q7：为什么每天固定要 50 家，而不是能抓多少算多少？**
50 家是「去重后有效客户」的下限，不是搜索上限。凑满 50 家能保证线索池每天稳定扩充、A/B 级候选充足；若只搜到十几家有效客户，线索会很快枯竭、市场切换频繁。因此规则是：多搜候选（60-70 家），经过去重 + 剔除同行 + 剔除信息不实 + **剔除无邮箱且无WhatsApp** 后，有效客户不足 50 家就换关键词/换城市/换工艺继续补搜凑满。

**Q8：每天的数据为什么要在桌面建「日期+国家」文件夹？**
方便你**每天一睁眼就能在桌面直接看到当天成果**，不用翻工作目录。文件夹命名 `YYYY-MM-DD-国家`（如 `2026-11-13-越南`），里面放当天的线索池、HTML 日报、开发信、待办清单。工作目录 `D:\masterbatch-leadgen\` 仍保留跨天累积的去重总池，两者分工：桌面是"当天快照"，工作目录是"长期数据库"。

**Q9：深挖为什么用浏览器（Chrome）而不是纯搜索？**
浏览器深挖能抓到**纯搜索拿不到的硬情报**：官网实时正文、联系页真实邮箱/电话、footer 里挂的 `facebook.com`/`zalo.me`/`wa.me`/`linkedin.com` 链接、Team/About 页的决策人姓名职位。这些是"搜索摘要"永远给不全的。但浏览器也可能被登录墙/反爬拦住，所以是**浏览器第一优先 + 搜索兜底**的组合，具体命令和降级规则见 `references/browser-deep-dive.md`。
